# JOIN — с кем сходить на событие

Мини-приложение и чат-бот в MAX для студентов: персональная афиша по интересам, отметка событий
по «Пушкинской карте» и поиск компании, чтобы пойти вместе.

Трек: «Досуг и развлечения» · направления «Персональная афиша» и «Льготные программы досуга».

## Проблема и пользователь

**Пользователь** — студент 14–22 лет (возраст «Пушкинской карты») в Москве или Санкт-Петербурге.

**Проблема.** Студент хочет сходить на концерт, спектакль или выставку, но:

- события разбросаны по разным афишам, и сопоставлять цену, дату и интересы приходится вручную;
- непонятно, какие билеты можно оплатить Пушкинской картой;
- часто не с кем пойти — и поход не случается.

**Основной сценарий:** открыть JOIN в MAX → выбрать событие в ленте (можно только «по Пушкинской») →
лайкнуть его → сразу увидеть «Напарник найден!» или получить его позже сообщением от бота →
договориться в чате (с готовыми вариантами первой фразы) → накануне бот напомнит о встрече.

**Результат для пользователя:** от выбора события до договорённости с напарником — без поиска
компании по чатам и без сверки нескольких афиш.

## Что используется в MAX

- **Мини-приложение, связанное с ботом.** Вход без пароля — по данным запуска MAX Bridge
  (`window.WebApp.initData`, подпись проверяется на сервере, `WebAppInitDataValidator`).
- **Бот** — точка входа и канал уведомлений: найден напарник, новые сообщения в личных и групповых
  чатах, напоминание накануне события (`EventReminderService`, ежедневно в 12:00 МСК).
  Кнопка `open_app` в уведомлении открывает мини-приложение **сразу на нужном экране** —
  в чате с напарником, а не на главной (payload `chat_<id>`, `gchat_<id>`, `event_<id>`, `pushkin`).
- **Команды бота:** `/start` — как работает JOIN и кнопки «Открыть афишу» / «По Пушкинской карте»;
  `/pushkin` — пять ближайших событий по Пушкинской карте в городе пользователя, каждое открывается
  кнопкой прямо на странице события; `/help`.
- **Вход через MAX вне мессенджера.** На сайте кнопка «Войти через MAX» открывает бота
  с одноразовым токеном (`/start login_<token>`); после «Начать» пользователь авторизуется на сайте
  автоматически. С компьютера — через QR-код. Так же привязывается MAX к уже существующему аккаунту
  (`link_<token>`).
- **Пушкинская карта.** События, которые можно оплатить картой, отмечены значком и фильтром;
  из карточки события можно перейти в официальное мини-приложение «Госуслуги Культура» в MAX.
- **«Позвать друга».** Кнопка на странице события отправляет его в любой чат MAX
  (`shareMaxContent`) ссылкой `https://max.ru/<бот>?startapp=event_<id>` — друг открывает
  то же событие в JOIN одним нажатием.
- **MAX Bridge:** стартовый параметр (deep-link'и и приглашения в компанию друзей), системная кнопка
  «Назад» на вложенных экранах, тактильный отклик на лайк и найденного напарника, сканер QR-кода
  (вступление в компанию по QR), открытие ссылок и профилей MAX внутри мессенджера.

## Архитектура

```
MAX (мини-приложение) ──HTTPS──┐
MAX Bot API ◄──webhook/REST──┐ │
                             │ ▼
                  nginx (TLS, /api → back, / → front)
                     │                  │
               back (Spring Boot)    front (React SPA, nginx)
                │    │    │
        PostgreSQL  парсеры  LLM (подсказки для первого сообщения)
```

| Компонент | Путь | Роль |
|---|---|---|
| Бэкенд | `back/` | REST API, WebSocket (STOMP) для чатов, вебхук бота MAX, парсеры афиш, уведомления |
| Мини-приложение | `front/` | Интерфейс пользователя; одна сборка работает в MAX, в Telegram и в браузере |
| Админ-панель | `admin/` | Модерация событий, чат поддержки |
| Прокси | `nginx/` | TLS, маршрутизация `/api`, `/ws` и статики |

Основные пакеты бэкенда (`back/src/main/java/com/join/back`):

- `web/controller` — REST-контроллеры, `MaxWebhookController` (события и команды бота);
- `service` — бизнес-логика: совпадения, чаты, группы, уведомления (`MaxNotificationService`),
  напоминания (`EventReminderService`), подборка `/pushkin` (`PushkinPicksService`), вход через MAX;
- `security` — проверка `initData` MAX/Telegram и JWT;
- `parser` — загрузка событий из внешних источников, нормализация, дедупликация, модерация;
- `db/changelog` — миграции Liquibase.

API описан в OpenAPI: `https://<DOMAIN>/swagger-ui/index.html` (спецификация — `/v3/api-docs`).

## Стек и зависимости

- Java 21, Spring Boot 3.2, Spring Data JPA, Liquibase, PostgreSQL 16 — версии в `back/build.gradle.kts`;
- React 19, TypeScript, MUI, Vite — версии зафиксированы в `front/package-lock.json`;

## Запуск

Нужны Docker и Docker Compose v2.

```bash
cp .env.example .env && docker compose up -d --build
```

Этого достаточно для локальной проверки: значения из `.env.example` рабочие для `localhost`.
Сборка всех образов без кэша занимает около 1,5 минуты (замер: 79 с, без учёта скачивания базовых образов).

- Если в `nginx/certs` нет `cert.crt` и `cert.key`, сервис `certs` создаёт самоподписанный сертификат
  для `DOMAIN`; для публичного домена положите туда настоящий сертификат.
- Если `JWT_SECRET` не задан, бэкенд создаёт случайный ключ при старте (сессии сбрасываются
  при перезапуске). Для постоянного стенда задайте его: `openssl rand -base64 48`.
- Для работы бота укажите реальный `MAX_BOT_TOKEN` и публичный `MAX_WEBHOOK_URL`.

После запуска: мини-приложение — `https://localhost/`, проверка API — `https://localhost/api/health`,
админ-панель — `http://localhost:8081`.

Миграции применяются автоматически при старте бэкенда. Загрузка событий запускается
по расписанию (ежедневно в 03:00) или вручную: `POST /api/admin/parser/run` с учётными данными администратора.

### Переменные окружения

Полный список с комментариями — в `.env.example`.

| Переменная | Обязательна | Назначение |
|---|---|---|
| `DOMAIN` | да | Домен мини-приложения; `localhost` для локального запуска (MAX открывает мини-приложения только по HTTPS) |
| `POSTGRES_PASSWORD` | да | Пароль БД |
| `JWT_SECRET` | для стенда | Ключ подписи JWT, `openssl rand -base64 48`; без него — случайный ключ на время работы |
| `MAX_BOT_TOKEN` | для бота | Токен бота из business.max.ru |
| `MAX_WEBHOOK_URL`, `MAX_WEBHOOK_SECRET` | для бота | Публичный адрес бэкенда для вебхука (`/api/max/webhook` добавляется сам) и секрет; пустой адрес — вебхук не регистрируется |
| `ADMIN_USERNAME`, `ADMIN_PASSWORD` | да | Доступ к админ-панели |
| `AI_API_KEY`, `AI_BASE_URL`, `AI_MODEL` | нет | OpenAI-совместимый API для подсказок первого сообщения; без ключа подсказки берутся из шаблонов |
| `TELEGRAM_BOT_TOKEN` | нет | Дополнительный клиент в Telegram; пустое значение отключает его |

### Настройка бота в MAX

1. В business.max.ru → «Чат-боты» получить токен и указать его в `MAX_BOT_TOKEN`.
2. В настройках бота привязать мини-приложение с адресом `https://<DOMAIN>/`.
3. Команды бота и подписка на вебхук настраиваются бэкендом при старте
   (вручную — `scripts/setup-max-bot.sh`).

## Как проверить основной сценарий

1. Открыть бота в MAX, нажать «Начать». **Ожидается:** бот объясняет сценарий в трёх шагах и показывает
   кнопки «Открыть афишу» и «По Пушкинской карте».
2. Нажать «Открыть афишу» и пройти короткую регистрацию: имя, возраст, город, вуз, интересы.
   **Ожидается:** мини-приложение открывается без пароля, в ленте — подсказка «Как найти, с кем сходить».
3. Включить фильтр «По Пушкинской» (или отправить боту `/pushkin`). **Ожидается:** только события
   со значком карты; в карточке события — переход в «Госуслуги Культура».
4. Лайкнуть событие. **Ожидается:** сообщение «Сохранили! … пришлём напарника в MAX».
5. Со второго аккаунта лайкнуть то же событие. **Ожидается:** у второго сразу появляется окно
   «Напарник найден!» с кнопкой «Написать …»; первому бот присылает сообщение с кнопкой,
   которая открывает **этот чат**.
6. Открыть чат. **Ожидается:** сверху — варианты первой фразы с именем собеседника; сообщения приходят
   мгновенно, а в бот — уведомление с кнопкой «Ответить».
7. Нажать «Позвать друга» на странице события. **Ожидается:** MAX предлагает выбрать чат; друг по ссылке
   попадает сразу на это событие.
8. Накануне события (12:00 МСК) оба напарника получают от бота напоминание с кнопкой в чат.
9. Вне MAX открыть сайт, нажать «Войти через MAX» и подтвердить в боте. **Ожидается:** сайт авторизуется в тот же аккаунт.

## Данные

| Источник | Что берём | Как |
|---|---|---|
| KudaGo | События Москвы и Санкт-Петербурга | Публичный API `kudago.com/public-api/v1.4` |
| Tickettoshow | Спектакли и концерты | Публичный API |
| Яндекс Афиша | Подборка «Пушкинская карта» — признак оплаты картой | Разбор публичных страниц подборки |
| Telegram-канал «Новой Оперы» | Студенческие билеты по промокоду | Публичная веб-версия канала |
| Справочник вузов | Вузы России с городами | Миграции `025`, `026`, `043` |

- Все события в ленте — реальные данные из этих источников со ссылкой на покупку билета у первоисточника.
- Признак «Пушкинская карта» берётся из подборки Яндекс Афиши. Это не официальный реестр:
  следующим шагом нужно брать его из PRO.Культура.РФ.
- Подсказки первой фразы в чате генерирует LLM. Они помечены как подсказки и не выдаются за факты.
- Тестовые и синтетические данные в базу не загружаются.

## Известные ограничения

- Для работы в MAX нужен публичный домен с валидным TLS-сертификатом. С самоподписанным
  сертификатом приложение открывается только в браузере (вход по email).
- Напоминание отправляется один раз в сутки по расписанию; события, добавленные позже 12:00 накануне,
  остаются без напоминания.
- Парсеры зависят от вёрстки и API сторонних площадок; при их изменении загрузка событий из источника
  останавливается, остальные источники продолжают работать.
- Города событий — пока Москва и Санкт-Петербург.
- Оплата билетов происходит на сайте продавца: JOIN не продаёт билеты и не работает с балансом Пушкинской карты.
- Timepad отключён (нужен токен API).
