# JOIN — с кем сходить на событие

Мини-приложение и чат-бот в MAX для студентов: персональная афиша города, события по «Пушкинской карте»
и поиск компании, чтобы пойти вместе.

Трек «Досуг и развлечения» · направления «Персональная афиша и навигатор событий» и «Льготные программы досуга».

| Для проверки | |
|---|---|
| Бот в MAX | [@t619_hakaton_max_bot](https://max.ru/t619_hakaton_max_bot) → «Начать» → «Открыть афишу» |
| Веб-версия (вне MAX: вход по email или через MAX) | https://2-27-20-14.sslip.io |
| Собственное API | `https://2-27-20-14.sslip.io/api`, спецификация — [`openapi.json`](openapi.json), проверки — [`DATA-API.yaml`](DATA-API.yaml) |
| Swagger UI | https://2-27-20-14.sslip.io/swagger-ui/index.html |
| Политика конфиденциальности | https://2-27-20-14.sslip.io/privacy |
| Тестовые учётные записи | на первом слайде презентации |

## Назначение решения

**Пользователь** — студент 14–22 лет (возраст «Пушкинской карты») в одном из 16 городов-миллионников России.

**Проблема.** Студент в свободный вечер хочет сходить на концерт, спектакль или выставку, но:

- события разбросаны по разным афишам, и сопоставлять дату, цену и интересы приходится вручную;
- непонятно, какие билеты можно оплатить Пушкинской картой;
- часто не с кем пойти — и поход не случается.

**Решение.** JOIN собирает события города из нескольких афиш в одну ленту, отмечает события по Пушкинской карте
и находит компанию среди тех, кто сохранил то же событие. Писать незнакомому человеку нельзя, пока он сам
не согласился пойти вместе: совпадение — это приглашение, а не чат.

**Результат для пользователя:** от выбора события до договорённости с напарником — в одном приложении,
без поиска компании по чатам и сверки нескольких афиш.

## Основной пользовательский сценарий

1. Открыть бота в MAX → «Открыть афишу» → короткая регистрация (имя, возраст, город, вуз, интересы, согласие
   на обработку данных). Пароль не нужен: пользователь определяется по подписанным данным запуска MAX.
2. Выбрать событие в ленте города (можно только «По Пушкинской») и сохранить его.
3. Когда то же событие сохраняет другой человек, оба сразу видят «Нашлась компания!» — в приложении и сообщением от бота.
4. Любой из двоих жмёт «Позвать пойти вместе»; второй отвечает «Пойдём» или «Не в этот раз» — прямо в сообщении бота.
5. После «Пойдём» открывается чат с готовыми вариантами первой фразы.
6. Накануне события бот напоминает о встрече, на следующий день спрашивает «Сходили вместе?».

## Что используется в MAX

- **Мини-приложение, связанное с ботом.** Вход без пароля по данным запуска MAX Bridge (`window.WebApp.initData`),
  подпись проверяется на сервере (`WebAppInitDataValidator`).
- **Бот — точка входа и канал уведомлений:** найден напарник, приглашение пойти вместе, новые сообщения,
  напоминание накануне события (`EventReminderService`, ежедневно в 12:00 МСК). Кнопка `open_app` в уведомлении
  открывает мини-приложение **сразу на нужном экране**: чат, событие, профиль найденного напарника
  (payload `chat_<id>`, `gchat_<id>`, `event_<id>`, `profile_<id>`, `pushkin`).
- **Ответ кнопками прямо в сообщении бота** (`message_callback`): «✅ Пойдём» / «Не в этот раз» на приглашение,
  «Да, сходили» / «Не получилось» на вопрос после события — без открытия приложения.
- **Команды бота:** `/start` — как работает JOIN; `/pushkin` — пять ближайших событий по Пушкинской карте в городе
  пользователя, каждое открывается кнопкой на странице события; `/help`.
- **«Позвать друга»:** страница события отправляется в любой чат MAX (`shareMaxContent`) ссылкой
  `https://max.ru/<бот>?startapp=event_<id>` — друг открывает то же событие в JOIN одним нажатием.
- **Пушкинская карта:** значок и фильтр в ленте, переход в официальное мини-приложение «Госуслуги Культура» в MAX.
- **Вход через MAX вне мессенджера:** на сайте «Войти через MAX» открывает бота с одноразовым токеном
  (`/start login_<token>`), с компьютера — по QR-коду. Так же MAX привязывается к аккаунту с email (`link_<token>`).
- **MAX Bridge:** стартовый параметр (deep-link'и и приглашения в компанию друзей), системная кнопка «Назад»
  на вложенных экранах, тактильный отклик на лайк и найденного напарника, сканер QR-кода, открытие ссылок
  и профилей MAX внутри мессенджера.
- **Мобильная и веб-версия MAX.** Одна сборка мини-приложения работает в обеих. Кнопка сканера QR-кода
  показывается, только если MAX даёт доступ к камере; в остальных случаях (например, на компьютере) в группу друзей
  вступают по коду приглашения («Группы» → «Группы друзей» → «По коду») или по ссылке.

## Состав и архитектура

```
MAX (мини-приложение) ──HTTPS──┐
MAX Bot API ◄──webhook/REST──┐ │
                             │ ▼
                  nginx (TLS; /api, /ws → back; / → front)
                     │                    │
               back (Spring Boot)      front (React SPA)
                │      │       │
        PostgreSQL  парсеры  LLM-подсказки (необязательно)
                     афиш
```

| Компонент | Путь | Роль |
|---|---|---|
| Бэкенд | `back/` | REST API, WebSocket (STOMP) для чатов, вебхук бота MAX, парсеры афиш, уведомления, миграции |
| Мини-приложение | `front/` | Интерфейс пользователя; одна сборка работает в MAX, в Telegram и в браузере |
| Админ-панель | `admin/` | Модерация событий, пользователи, чат поддержки |
| Прокси | `nginx/` | TLS, маршрутизация `/api`, `/ws`, `/swagger-ui`, статики |
| Android | [join-mobile](https://github.com/arklual/join-mobile) | Обёртка Capacitor над тем же `front/src` (отдельный репозиторий) |

Основные пакеты бэкенда (`back/src/main/java/com/join/back`):

- `web/controller` — REST-контроллеры и `MaxWebhookController` (события и команды бота);
- `service` — бизнес-логика: совпадения (`MatchService`), приглашения (`ContactRequestService`), чаты, компании,
  уведомления (`MaxNotificationService`), напоминания и «Сходили вместе?», возрастные правила (`AgePolicy`),
  удаление аккаунта (`AccountDeletionService`);
- `security` — проверка `initData` MAX/Telegram и JWT;
- `parser` — загрузка событий из источников, нормализация, объединение дублей, модерация;
- `resources/db/changelog` — миграции Liquibase.

## Запуск

Нужны Docker и Docker Compose v2. Одна команда поднимает все компоненты (PostgreSQL, бэкенд, мини-приложение,
админ-панель, nginx):

```bash
cp .env.example .env && docker compose up -d --build
```

Значения из `.env.example` рабочие для `localhost`. После запуска:

- мини-приложение — `https://localhost/` (сертификат самоподписанный — браузер попросит подтвердить);
- проверка API — `https://localhost/api/health` → `{"status":"UP","db":"UP"}`;
- Swagger UI — `https://localhost/swagger-ui/index.html`;
- админ-панель — `http://localhost:8081` (`ADMIN_USERNAME` / `ADMIN_PASSWORD` из `.env`).

Что происходит при запуске:

- сервис `certs` создаёт самоподписанный сертификат для `DOMAIN`, если в `nginx/certs` нет `cert.crt` и `cert.key`;
- бэкенд применяет миграции Liquibase и, если база пустая, в фоне загружает события из источников (1–3 минуты);
  дальше загрузка идёт по расписанию, ежедневно в 03:00;
- `nginx` открывает порты только после того, как бэкенд прошёл проверку здоровья (`/api/health` проверяет базу).

Сборка всех образов без кэша занимает около минуты (замер: 70 с на сервере с 8 vCPU, без учёта скачивания базовых образов).

### Используемые порты

| Порт на хосте | Сервис | Настройка |
|---|---|---|
| 80 | nginx, HTTP (редирект на HTTPS) | `HTTP_PORT` |
| 443 | nginx, HTTPS: мини-приложение, `/api`, `/ws`, Swagger | `HTTPS_PORT` |
| 8081 | админ-панель | `ADMIN_PORT` |

Внутри сети Docker: бэкенд — 8080, PostgreSQL — 5432, front и admin — 80; наружу они не публикуются.
Если 80 или 443 заняты, поменяйте `HTTP_PORT` / `HTTPS_PORT` в `.env` (для работы внутри MAX нужен 443 на публичном домене).

### Переменные окружения

Полный список с комментариями — в `.env.example`. Рабочих токенов и паролей в репозитории нет.

| Переменная | Обязательна | Назначение |
|---|---|---|
| `DOMAIN` | да | Домен мини-приложения; `localhost` для локального запуска |
| `POSTGRES_PASSWORD` | да | Пароль БД (`POSTGRES_DB`, `POSTGRES_USER` — имя базы и пользователя) |
| `ADMIN_USERNAME`, `ADMIN_PASSWORD` | да | Доступ к админ-панели и служебным методам `/api/admin/**` |
| `JWT_SECRET` | для стенда | Ключ подписи JWT: `openssl rand -base64 48`. Пусто — случайный ключ при старте, сессии сбрасываются при перезапуске |
| `MAX_BOT_TOKEN` | для бота | Токен бота из business.max.ru; им же проверяется подпись `initData` |
| `MAX_WEBHOOK_URL`, `MAX_WEBHOOK_SECRET` | для бота | Публичный HTTPS-адрес бэкенда для вебхука (`/api/max/webhook` добавляется сам) и секрет; пусто — вебхук не регистрируется |
| `HTTP_PORT`, `HTTPS_PORT`, `ADMIN_PORT` | нет | Порты на хосте (80, 443, 8081) |
| `AI_API_KEY`, `AI_BASE_URL`, `AI_MODEL` | нет | OpenAI-совместимый API для подсказок первой фразы; без ключа подсказки берутся из шаблонов |
| `JOIN_CITIES` | нет | Города JOIN (по умолчанию 16 городов-миллионников) |
| `CULTURE_RU_API_KEY` | нет | Партнёрский ключ PRO.Культура.РФ — официальный реестр событий Пушкинской карты; без ключа источник выключен |
| `TELEGRAM_BOT_TOKEN`, `TELEGRAM_WEBHOOK_SECRET` | нет | Дополнительный клиент в Telegram; пусто — выключен |

### Остановка и повторный запуск

```bash
docker compose stop                   # остановить, данные и контейнеры сохраняются
docker compose start                  # запустить снова
docker compose up -d --build          # пересобрать после изменений и перезапустить
docker compose restart back           # перезапустить один сервис
docker compose logs -f back           # логи бэкенда
docker compose down                   # удалить контейнеры; база остаётся в томе postgres_data
docker compose down -v                # удалить и данные: следующий запуск начнётся с пустой базы
```

Повторный запуск идёт с теми же данными; миграции применяются только новые. После `down -v` события загрузятся заново.

### Настройка бота в MAX

1. В business.max.ru → «Чат-боты» получить токен и указать его в `MAX_BOT_TOKEN`.
2. В настройках бота привязать мини-приложение с адресом `https://<DOMAIN>/`.
3. Указать `MAX_WEBHOOK_URL=https://<DOMAIN>`. Подписка на вебхук и команды бота настраиваются бэкендом
   при старте (вручную — `scripts/setup-max-bot.sh`).

- Все события в ленте — реальные данные из этих источников со ссылкой на покупку билета у первоисточника.
  Тестовые и синтетические события в базу не загружаются.
- Одно событие из нескольких источников показывается один раз: совпадают город, дата и название; вторая площадка
  дополняет карточку ценой и отметкой Пушкинской карты.
- **Допущение:** официальный источник для Пушкинской карты — PRO.Культура.РФ, но на демо-стенде партнёрского
  ключа нет, поэтому источник выключен, а признак карты берётся из данных Кассира и подборки Яндекс Афиши.
  Интеграция с PRO.Культура.РФ реализована по документации API 2.5 и включается переменной `CULTURE_RU_API_KEY`.
- Подсказки первой фразы генерирует LLM; в интерфейсе они помечены как подсказки и не выдаются за факты.

### Персональные данные

- Храним профиль (имя, пол, возраст, город, вуз, интересы, фото и «о себе» — по желанию), идентификатор MAX
  или email с хешем пароля, действия в JOIN (сохранённые события, совпадения, сообщения, компании).
- При регистрации обязательно согласие с [политикой конфиденциальности](https://2-27-20-14.sslip.io/privacy)
  (`personal_data_consent_at`); у аккаунтов, созданных раньше, согласие спрашивается при следующем входе.
- JOIN доступен с 14 лет. Пользователи 14–17 лет получают совпадения, видят профили и открытые компании только
  сверстников, взрослые — только взрослых (`AgePolicy`).
- В LLM передаются только категории интересов и данные о событии — без имени, возраста и других данных профиля.
- Пользователь удаляет аккаунт сам: «Профиль» → «Удалить аккаунт» (`DELETE /api/users/me`) — это и есть отзыв согласия.

## Тестовые данные и учётные записи

- Заранее подготовленных данных в базе нет: события загружаются из источников при первом запуске и каждую ночь.
  Загрузку можно запустить вручную: `POST /api/admin/parser/run` с учётными данными администратора.
- Тестовые учётные записи демо-стенда (пользователи А и Б) — на первом слайде презентации.
- Локально пользователей создают через регистрацию по email на `https://localhost/register` или запросом:

  ```bash
  curl -k https://localhost/api/auth/register -H 'Content-Type: application/json' -d '{"email":"a@example.com",
    "password":"password123","firstName":"Аня","age":20,"gender":"FEMALE","city":"Казань",
    "interests":["MUSIC"],"personalDataConsent":true}'
  ```

- Для совпадения нужны два аккаунта в одном городе. Второй удобно завести в окне инкогнито.
- Для проверок API используются только эти два аккаунта; город и текст сообщения заданы в `test_data`
  файла `DATA-API.yaml`. Событие выбирается из текущей ленты, в конце проверки лайки снимаются — совпадение
  и чат удаляются, данные возвращаются в исходное состояние.

## Собственное API

- Базовый адрес: `https://2-27-20-14.sslip.io` (локально — `https://localhost`), методы — под `/api`.
- Спецификация OpenAPI 3.0: [`openapi.json`](openapi.json) — снимок `/v3/api-docs` демо-стенда
  (генерируется из кода, Swagger UI — `/swagger-ui/index.html`). Внутренние методы админ-панели и вебхуки ботов
  в публичную спецификацию не входят.
- Авторизация: `Authorization: Bearer <JWT>` (выдают `POST /api/auth/login` и `/api/auth/register`)
  или `X-Max-Init-Data: <initData>` внутри MAX. Без авторизации защищённые методы отвечают `403`.
- Ошибки — JSON вида `{"error": "…"}`, у части ответов есть `message` и `code` (`VALIDATION_FAILED`,
  `BAD_CREDENTIALS`, `EMAIL_TAKEN`, …).
- Обязательные проверки — [`DATA-API.yaml`](DATA-API.yaml): 19 шагов основного сценария (вход, афиша, фильтр по
  Пушкинской карте, лайк двумя пользователями → совпадение → приглашение → согласие → чат → уборка).
  Запустить все проверки:

  ```bash
  export JOIN_USER_A_EMAIL=… JOIN_USER_A_PASSWORD=… JOIN_USER_B_EMAIL=… JOIN_USER_B_PASSWORD=…
  pip install -r scripts/requirements.txt && python3 scripts/check-api.py
  # локальный стенд: python3 scripts/check-api.py --base-url https://localhost --insecure
  ```

## Пошаговый сценарий проверки

В MAX (мобильное приложение или web.max.ru) — два аккаунта MAX:

1. Открыть [бота](https://max.ru/t619_hakaton_max_bot), нажать «Начать».
   **Ожидается:** бот объясняет сценарий в трёх шагах и показывает кнопки «Открыть афишу» и «По Пушкинской карте».
2. «Открыть афишу» → регистрация: имя, возраст, город, вуз, интересы, галочка согласия.
   **Ожидается:** мини-приложение открывается без пароля; без галочки или с возрастом младше 14 форма
   не отправляется и объясняет почему; в ленте — события выбранного города.
3. Включить фильтр «По Пушкинской» (или отправить боту `/pushkin`).
   **Ожидается:** только события со значком карты; в карточке события — переход в «Госуслуги Культура».
4. Сохранить событие (♥). **Ожидается:** «Сохранили! … пришлём напарника в MAX».
5. Со второго аккаунта сохранить то же событие.
   **Ожидается:** у второго сразу окно «Нашлась компания!» с кнопкой «Позвать пойти вместе»; первому бот присылает
   то же с кнопкой «🤝 Позвать пойти вместе». Чата ещё нет — написать незнакомцу нельзя.
6. Нажать «Позвать пойти вместе».
   **Ожидается:** второму бот присылает «… зовёт вас пойти на … вместе» с кнопками «✅ Пойдём» / «Не в этот раз»
   (то же — в приложении: «Чаты» → «Нашлась компания»).
7. Ответить «Пойдём». **Ожидается:** открывается чат; пригласившему бот пишет «— «пойдём!» Чат открыт».
   Сверху в чате — варианты первой фразы; сообщения приходят мгновенно, в бот — уведомление с кнопкой «Ответить».
8. Нажать «Позвать друга» на странице события.
   **Ожидается:** MAX предлагает выбрать чат; друг по ссылке попадает сразу на это событие.
9. Накануне события в 12:00 МСК оба получают от бота напоминание с кнопкой в чат; на следующий день после
   события — вопрос «Сходили вместе?», ответ кнопкой сохраняется, сообщение сменяется благодарностью.
10. «Профиль» → «Удалить аккаунт». **Ожидается:** после подтверждения аккаунт удалён, при следующем открытии —
    снова регистрация.

Вне MAX — https://2-27-20-14.sslip.io: вход по email тестового пользователя или «Войти через MAX» (подтвердить в боте,
с компьютера — по QR-коду). **Ожидается:** сайт открывает тот же аккаунт, что и в MAX.

### Примеры ожидаемого поведения

| Ситуация | Поведение |
|---|---|
| Регистрация без согласия на обработку данных | Отказ: «Нужно согласие на обработку персональных данных» (API — `400`, `VALIDATION_FAILED`) |
| Возраст младше 14 | Отказ: «JOIN доступен с 14 лет» |
| Пользователю 16, событие сохранил взрослый | Совпадения нет; профили и открытые компании друг друга не видны |
| Лайк снят после совпадения | Совпадение и чат удаляются (приложение предупреждает) |
| Одиннадцатый лайк за сутки | «Сегодня можно лайкнуть не больше 10 событий — возвращайся завтра» |
| Второй отказался от приглашения | Первому об отказе не сообщается, чат не открывается |
| Пользователь в чёрном списке | Совпадений и сообщений с ним нет, в его компанию не вступить |
| Экран упал с ошибкой | «Что-то пошло не так» с возвратом в афишу, остальное приложение работает |
| Нет связи с сервером при запуске | «Не удалось подключиться к серверу» с кнопкой повтора |

## Безопасность

- Пользователь в MAX определяется только по подписанным данным запуска: подпись `initData` проверяется
  на сервере токеном бота. Вне мессенджера — JWT.
- Вебхук бота принимает запросы только с секретом `X-Max-Bot-Api-Secret`.
- CORS и WebSocket открыты только для домена мини-приложения и Android-приложения (`CorsConfig`).
- Одноразовые токены входа (10 минут) и привязки MAX (15 минут) гасятся после использования.
- После 10 неудачных попыток входа для email или с одного адреса вход блокируется на 15 минут.
- Возрастные правила и согласие на обработку данных проверяются на сервере, а не только в интерфейсе.
- Секреты передаются только через переменные окружения; в репозитории их нет.

## Известные ограничения

- Для работы внутри MAX нужен публичный домен с валидным TLS-сертификатом. С самоподписанным сертификатом
  приложение открывается только в браузере (вход по email).
- Возраст пользователь указывает сам; подтверждения возраста нет. Нарушителя можно заблокировать и сообщить в поддержку.
- Демо-стенд — пилот, он размещён за пределами России. Для публичного запуска нужен сервер в России (ч. 5 ст. 18 152-ФЗ).
- Сканер QR-кода работает там, где MAX даёт доступ к камере; без него в группу друзей вступают по коду или ссылке.
- Напоминание и вопрос «Сходили вместе?» отправляются раз в сутки в 12:00 МСК; события, добавленные позже 12:00
  накануне, остаются без напоминания.
- Парсеры зависят от вёрстки и API сторонних площадок; при их изменении останавливается загрузка из одного
  источника, остальные продолжают работать.
- Города — 16 миллионников (`JOIN_CITIES`). KudaGo покрывает только Москву, Петербург, Казань, Екатеринбург
  и Нижний Новгород, «Глазами инженера» — Москву и Петербург; Кассир.ру, Яндекс Афиша и Timepad — все 16 городов.
  Время событий — местное для города.
- Постоянные экспозиции и давно идущие спектакли без ближайшей даты сеанса не показываются.
- JOIN не продаёт билеты и не работает с балансом Пушкинской карты: оплата — на сайте продавца.
- Без авторизации API отвечает `403`, а не `401`.
